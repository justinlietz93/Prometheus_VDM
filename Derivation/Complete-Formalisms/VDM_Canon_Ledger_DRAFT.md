# VDM Canon Ledger (Draft)

Last updated: 2026-03-20

**Scope:** Canonical ledger for the VDM stack. This page records the root law, named consequence branches, completed formalisms, active near-term formalizations, and inheritance rules. It is designed to prevent status-smear between what is first earned, what is inherited, what is restated locally, and what is still being packaged.

**Rules:**
- Use this ledger as the single status reference for canon.
- Later papers inherit all theorem-grade results closed in declared dependency papers.
- A later paper may restate inherited results locally, but must label them as inherited/recalled rather than first-earned.
- Do not mark a branch as "open" when the machinery is already developed and only the formal writeup remains.
- Separate document-status from theory-status.

## Status Vocabulary

- **Closed here** — First theorem-grade earn-point is closed in the named paper.
- **Inherited-closed** — Closed upstream and lawfully reused downstream.
- **Restated locally** — Replayed for branch continuity, but not first-earned here.
- **Active near-term formalization** — Machinery is considered in hand; formal paper/package expected soon.
- **Exploratory** — Interpretive or discussion-layer material, not load-bearing proof spine.

## Canon Inheritance Policy

1. Every later paper inherits all theorem-grade content closed in its declared dependency papers.
2. A later paper must not describe an inherited result as missing, optional, merely suggestive, or first-earned locally.
3. If a later paper replays an inherited result for branch continuity, it must label it **restated locally** or **recalled from upstream**.
4. If a branch is conceptually fixed and expected to be written up soon, mark it **active near-term formalization**, not “open” in a vague way.
5. Interpretive overlays must not be allowed to overwrite first-earned ownership.

## Special Ownership Notes

### Ownership of \(\pi\)

- **CF00 owns the primitive \(\pi\)-anchoring.**
- CF00 is the first earn-point for the continuous ORS orbit and the definition
  \[
  \pi := \inf\{\theta>0 : R_\theta = -I\}.
  \]
- Circle / disk / area expressions are downstream realizations in CF00, not primitive definitions.
- **CF13 inherits this base fact** and extends the branch into half-turn identity, transcendence, chirality, and Nielsen–Ninomiya consequences.
- CF13 may restate the \(\pi\)-anchoring locally, but must not sound like it first repairs or first discovers primitive \(\pi\).

### Constructive vs Explanatory Split for Chirality

- **CF08** is the constructive domain-wall / overlap / GW paper.
- **CF13** is the deeper invariant-geometric explanation layer for why this construction is the lawful response to the obstruction.
- CF08 should not attribute first ownership of primitive \(\pi\) to CF13.

### Dark Sector Status

- **CF11** is not a new-particle postulate paper.
- It is a derived-limit interpretation layer built on already-earned metriplectic and transport structure.
- Later cosmology-facing papers should inherit that status rather than describe it as a primitive ontology insertion.

### Least Action Branch

- **CF14** should be tracked as imminent formal closure, not as remote speculation.
- The right status wording is **active near-term formalization** until the theorem-bearing paper is frozen.

## Immediate Canon Checks for Agents / Editors

Before revising any paper, answer these five questions:

1. What is **first earned here**?
2. What is **inherited and already closed upstream**?
3. What is **restated locally only for continuity**?
4. What is **downstream-but-not-missing**?
5. What is **active near-term formalization** vs genuinely exploratory?

If a sentence cannot be placed in one of those buckets, it is at risk of status-smear.
