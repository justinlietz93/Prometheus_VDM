## Recommended rule

For the HRDAP section, the manuscript should explicitly state three things:

### 1. Allowed semantics inside current scope
What words and meanings are legal **before HRDAP closes**.

These should stay limited to things already earned at v18, such as:
- origin
- realizable
- flat / non-flat
- differentiated articulation
- invariant-bearing articulation
- lowest-resolution degree after origin
- higher-resolution degree as schematic target
- lower-resolution degree not sufficient as sole determination
- additional internal determination as character consequence *if* higher-resolution degree is admitted
- local settlement / global non-resolution
- dependence order

### 2. Blocked semantics inside current scope
What cannot be used to argue for HRDAP.

These should include:
- apartness
- contextual noncoincidence as if already closed
- nodehood
- branch / tree / graph structure
- locality
- metricity
- boundary completion
- carrier-like support
- recursive refinement as though already active
- geometric dimension language

### 3. Unlocked semantics if HRDAP closes
What becomes newly available **only after** the section closes.

Likely:
- actual admitted higher-resolution degree
- stronger use of additional internal determination
- contextual noncoincidence as a live next question
- apartness as a now-approachable downstream target
- later RRP attack from a cleaner base

## Best implementation

The manuscript should add a short section or boxed note for each open burden:

- **Current semantic budget**
- **Blocked imports**
- **If this burden closes, the following definitions become newly live**

That would make the dependency ladder operational, not just descriptive.

## Bottom line

This is a good idea and it is timely.

v18 made the theorem spine clean enough that the next danger is now almost entirely **semantic overreach inside HRDAP**. A semantic-budget ledger is the right guardrail for that next pass.
